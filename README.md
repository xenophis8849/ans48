# ans48

实时全带降噪库：48 kHz / 44.1 kHz 单声道，C 接口，Android（arm64-v8a、armeabi-v7a）预编译库，模型编在库里。

三档：

| 档位 | 用途 | 窗长 | 算法延迟（48 kHz / 44.1 kHz） | 强度范围 |
|---|---|---|---|---|
| `ANS48_MODE_MONITOR` | 耳返（自己听自己的声音，延迟敏感） | 256 样本 | 5.3 ms / 5.8 ms | 0 ~ 2 |
| `ANS48_MODE_STREAM` | 录音 / 推流（给别人听的成品） | 1024 样本 | 21.3 ms / 23.2 ms | 0 ~ 2 |
| 频谱档（`ans48_create_spec`） | 挂在 aec48 的频谱回调上，直接在回声消除后的频谱上降噪 | 1536 样本（由 aec48 分帧） | 0（不另加延迟，整体只有 aec48 自己的延迟） | 0 ~ 2 |

强度 = 掩码指数 γ：输出谱 = 输入谱 × 掩码^γ。0 = 原样直通（只有延迟），1 = 模型全档，>1 比全档压得更狠。

频谱档是跨项目的联动接口，见「⚠ 联动接口：频谱档（与 aec48 串接）」一节。

## 快速开始

### 用预编译库

把 `include/ans48.h` 与 `prebuilt/<ABI>/libans48.so` 加进工程（例如放到 `app/src/main/jniLibs/<ABI>/`），在自己的 native 代码里 `#include "ans48.h"` 并链接 `libans48.so`。库只依赖系统 libc / libm，C++ 运行时静态链接在库内。

### 从源码编译

```sh
ANDROID_NDK=/path/to/ndk tools/build_android.sh        # 出 prebuilt/<ABI>/libans48.so 与 build-android-<ABI>/ 下的测试程序
cmake -S . -B build-host && cmake --build build-host  # 主机版（自检用）
```

### 最小调用

```c
#include "ans48.h"

Ans48* dn = ans48_create(48000, ANS48_MODE_MONITOR);   // 失败返回 NULL
ans48_set_strength(dn, 1.0f);                           // 可在任意线程调，下一帧生效

// 音频回调里：任意长度，in 与 out 可以同址
ans48_process(dn, in, out, frames);                     // float，±1 满幅
// 或 ans48_process_s16(dn, in16, out16, frames);

ans48_destroy(dn);
```

## 接口

| 函数 | 说明 |
|---|---|
| `Ans48* ans48_create(int sample_rate, int mode)` | 建实例。`sample_rate` 只支持 48000、44100；`mode` 为 `ANS48_MODE_MONITOR` 或 `ANS48_MODE_STREAM`。失败（参数不支持、内存不足）返回 NULL，不会结束宿主进程。初始强度 1。 |
| `int ans48_process(Ans48*, const float* in, float* out, int n)` | 处理 n 个样本，任意长度，`out` 可以与 `in` 同址。返回 0；参数无效返回 −1。 |
| `int ans48_process_s16(Ans48*, const short* in, short* out, int n)` | int16 版，与 float 版输出一致（量化到 int16）。 |
| `float ans48_set_strength(Ans48*, float gamma)` | 设强度，截到 `[0, ans48_max_strength]`，NaN 忽略；返回实际生效的值。可在任意线程调用。 |
| `float ans48_get_strength(const Ans48*)` / `float ans48_max_strength(const Ans48*)` | 当前强度 / 该档上限（耳返 2、推流 1）。 |
| `int ans48_latency_samples(const Ans48*)` | 输出相对输入的固定延迟（样本数）= 窗长。 |
| `void ans48_reset(Ans48*)` | 清空内部状态（换歌、断流后重新开始）；强度不变。不要与 `process` 并发调用。 |
| `void ans48_stats(const Ans48*, double out3[3])` | 最近一秒每帧平均处理耗时 ms、最大 ms、已处理样本数。一帧 = 一个 hop（窗长的一半）。 |
| `void ans48_destroy(Ans48*)` / `const char* ans48_version(void)` | 销毁 / 版本与模型标识。 |

### 延迟

输出比输入晚 `ans48_latency_samples()` 个样本（= 窗长：耳返 256、推流 1024）。这是算法延迟，不含设备与应用的音频缓冲。开头这一段是启动段，输出接近 0（重叠相加起步时的舍入余量，不超过 −60 dBFS）。强度 0 时输出就是输入延迟这么多样本（自检里有这一项）。

### 线程

- 一个实例同一时刻只能在一个线程里 `process`。不同实例互不影响，可以在不同线程同时用。
- `ans48_set_strength` 可以在任意线程调用（原子变量，`process` 每次开始时读一次）。
- `process` / `process_s16` 不分配内存、不加锁、不做文件读写，可以直接在音频回调里调用。

## 接入要点

- 采样率要与实际流一致；只支持 48000 与 44100，其他采样率请在外部重采样后再送进来（或换用支持的采样率采集）。
- 每次调用的块长任意，内部按 hop（耳返 128、推流 512 样本）凑帧；块长等于 hop 的整数倍时每次调用的耗时最均匀。
- 耳返档每 128 样本（48 kHz 下 2.7 ms）算一帧，**建议放在大 / 中核上跑**（小核按真实节奏仍偶有块超时，见性能表）；回调块长小于 128 时，有的回调不算帧、有的回调算一帧，单次回调的耗时会不均匀。推流档每 512 样本算一帧，小核也跑得下。
- 降噪放在回声消除之后（对回声消除的输出降噪）。两者都会引入延迟，总延迟相加。

## ⚠ 联动接口：频谱档（与 aec48 串接）

> **这一节是跨项目的接口契约，与 aec48 README 的「⚠ 联动接口：频谱回调（与降噪库串接）」一一对应。帧格式、调用时序、开关语义以 aec48 那一节为准**；本库按其中的契约版本实现，头文件里有同名的版本宏。
> aec48 一侧提升契约版本时，本库要核对、改实现、提升 `ANS48_SPEC_CONTRACT_VERSION` 后再发布；本节的「契约变更记录」同步记一行。

**当前实现的契约版本：1**（库 0.3.0 起；`ANS48_SPEC_CONTRACT_VERSION` = 1）。

### 用途与边界

推流档本身要分帧，窗 1024，算法延迟 21.3 ms。如果串在回声消除后面，两段延迟会叠加。频谱档不自己分帧：aec48 每处理一块，在把输出频谱合成回声音之前调用挂上的回调，频谱档就在这份频谱上原地乘掩码^γ。所以不另加延迟，也省一次正反变换。两个库各自发布、互不链接，只靠帧格式约定对接。频谱档只降噪，不处理回声。

### 接法

```c
#include "aec48.h"
#include "ans48.h"
#if AEC48_SPEC_CONTRACT_VERSION != ANS48_SPEC_CONTRACT_VERSION
#error "aec48 与 ans48 的联动接口契约版本不一致"
#endif

int sr, nfft, hop, win;
aec48_spec_format(aec, &sr, &nfft, &hop, &win);
Ans48* n = ans48_create_spec(sr, nfft, hop, win);      // 与本库实现的契约不符返回 NULL：那就不要挂
aec48_set_spec_hook(aec, ans48_spec_frame, n);          // 处理开始前挂好
...
aec48_set_spec_hook(aec, NULL, NULL);                   // 不处理时摘掉
ans48_destroy(n);
```

`ans48_create_spec` 逐项核对：采样率 48000 / 44100，窗长 1536，帧移 384，窗型 1（周期 sqrt-Hann）。内嵌模型的分帧也会一并核对，对不上同样返回 NULL。频谱档实例上调 `ans48_process` / `ans48_process_s16` 返回 −1；`ans48_latency_samples` 返回 0；强度、复位、统计、销毁与另两档相同。

### 强度与临时关闭

- 强度 `ans48_set_strength(n, γ)`，范围 0 ~ 2，可在任意线程调用，下一帧生效。
- **运行中要临时关降噪，优先用 `ans48_set_strength(n, 0)`**。网络照常逐帧运行，输出频谱原样返回，与不挂回调逐样本相同（自检里有这一项）。跨帧记忆保持连续，重新打开时没有过渡问题。
- 也可以用 aec48 的挂钩开关 `aec48_set_spec_hook_enabled`。关掉期间本库收不到帧，跨帧记忆停在关之前；重新打开后，开头一小段会带着旧记忆处理。aec48 那边另有 3 块的重叠相加过渡。
- 换歌、断流后要从头开始：在不处理时调 `ans48_reset(n)`。

### 线程与实时

`ans48_spec_frame` 在 aec48 的处理线程里同步执行：不分配内存、不加锁、不读写文件、不阻塞。同一实例同一时刻只能被一个 aec48 实例调用。它的耗时会计入 aec48 那一块的处理耗时（`aec48_stats`），评估最坏情况时要把两者放在一起看。

### 自检

- `ans48_speccheck <向量目录> 00d2fda6`：按契约自做分析 / 合成（左补 768 个零后因果分帧、周期 sqrt-Hann、不归一化 DFT；合成时 IDFT/N 乘窗、重叠相加、除以窗平方的重叠和），逐帧调用 `ans48_spec_frame`，与参照波形逐样本比。另查参数核对、γ = 0 恒等、复位后与新实例相同。
- `ans48_aecchain <向量目录> 00d2fda6`：链接 aec48 的主机构建。aec48 直通时挂上频谱档，输出应等于参照再晚 `aec48_latency_samples` 个样本；aec48 开、强度 0 时，输出应与不挂回调逐样本相同；同时报每块耗时。

### 联调结果（ans48 0.3.0 × aec48 0.5.2，主机）

`test/ans48_aecjoint` 在带回声的录音上把两个库串起来跑，写出各种接法的输出，并核对运行中切换的行为。它只在 `-DANS48_AEC48_DIR=<aec48 目录>` 时编。素材是公开的 ICASSP 2023 AEC Challenge 盲测集（48 kHz），共 25 条：双讲 13 条、远端单讲 6 条、近端单讲 6 条。

```sh
ans48_aecjoint <mic.pcm> <ref.pcm> 48000 <输出目录>
```

| 项目 | 怎么量 | 结果 |
|---|---|---|
| 输出 | 各接法输出逐样本查是否有限 | 25 条全部有限 |
| 残余回声 | 远端单讲（只有回声）挂频谱档 γ1 与 aec48 单独比整段电平 | 6 条都更低（−0.7 ~ −2.4 dB），没有被放大 |
| 电平 | 整段电平与 aec48 单独比 | 频谱档 γ1 中位 −0.67 dB、γ2 中位 −1.34 dB；与旧接法（aec48 输出合成后再串推流档）24 条相差 ≤ 0.2 dB，1 条（远端单讲）频谱档多压 1.7 dB；旧接法多 1024 样本延迟 |
| 用强度 0 临时关（每 2 s 在 1 ↔ 0 之间切） | 帧级：包一层回调逐帧记下进 / 出频谱。稳态：过渡带（切换点前后各 1536 样本）之外按浮点位逐样本比 | 441 次切换（在执行处计数，全部分析到）。113 724 帧里，强度为 1 的帧与一直挂着那次的同一帧逐位相同，强度为 0 的帧原样返回，0 帧例外。稳态 3993 万个样本与参照（开 = 一直挂着，关 = aec48 单独）逐位相同。即频谱档在切换时不引入任何额外变化，输出上的过渡只是 aec48 合成时的重叠相加 |
| 用 aec48 挂钩开关临时关（每 2 s 关 / 开） | 同上；重开后按 384 样本块看与一直挂着的误差能量（相对一直挂着那块的能量，那块低于 −70 dBFS 的近静音块不计），持续 ≥ 0.5 s 低于 −40 dB 才算收敛（持续时长只算可听块） | 关着时回调确实不被调用（帧数与开着的块数相符），关的段稳态与 aec48 单独逐位相同。重开后本库带着关之前的跨帧记忆：误差中位数 0–0.1 s −36 dB、0.3–1.5 s 约 −42 dB，但 90% 分位只有 −14 ~ −22 dB，个别段比输出本身还大。重开 210 次，在观察窗（约 1.5 s）内收敛的 53 次、没收敛的 151 次、可听块都达标但合计不到 0.5 s（证据不足）2 次、观察不足 3 次、近静音 1 次 |

结论：**运行中临时关降噪用 `ans48_set_strength(n, 0)`**，切换不引入任何变化。用挂钩开关时，重新打开后的一两秒乃至更久，降噪会与一直开着明显不同。

```sh
cd test/vec
../../build-host/ans48_check 00d2fda6_in48k.pcm 48000 monitor 1 00d2fda6_monitor_48k_g1.pcm
../../build-host/ans48_check 00d2fda6_in48k.pcm 48000 monitor 2 00d2fda6_monitor_48k_g2.pcm
../../build-host/ans48_check 00d2fda6_in441.pcm 44100 monitor 1 00d2fda6_monitor_441_g1.pcm
../../build-host/ans48_check 00d2fda6_in441.pcm 44100 monitor 2 00d2fda6_monitor_441_g2.pcm
../../build-host/ans48_check 00d2fda6_in48k.pcm 48000 stream 1 00d2fda6_stream_48k_g1.pcm
../../build-host/ans48_check 00d2fda6_in441.pcm 44100 stream 1 00d2fda6_stream_441_g1.pcm
```

期望输出由训练端的流式参照实现处理同一段录音得到。通过标准：库的输出按延迟挪齐后，与期望输出的差值能量低 ≥ 50 dB（实测 −97 ~ −103 dB，最大差 1 LSB，即 int16 取整的量级）。

`test/ans48_robust` 检查接口边界（主机与手机都能跑，全部通过返回 0）：不支持的参数返回 NULL / −1；强度 0 时输出 = 输入延迟窗长；块长 1 / 7 / 96 / 383 / 480 / 1000 / 4096 / 整段与原地处理逐样本相同；int16 与 float 一致；强度越大输出能量不增、超范围截断、NaN 忽略；reset 后与新实例相同；处理期不分配内存；反复创建 / 销毁不漏内存；多线程并发创建与处理；处理中从另一线程改强度。

```sh
./build-host/ans48_robust test/vec/00d2fda6_in48k.pcm test/vec/00d2fda6_in441.pcm
./build-host/ans48_wrap test/vec/00d2fda6_in48k.pcm     # 输出缓冲计数器跨过 2^32 / 2^64 回绕点时输出不中断
./build-host/ans48_oom                                   # 建实例时每一次内存分配逐次失败：都返回 NULL、不崩溃
```

网络推理另有逐层核对（权重导出时同时录下参照网络每一块在两帧输入下的输出，手写实现逐块比较；主机与手机、arm64 与 armv7 均通过，最大差 1e-5 量级）。该核对依赖训练端代码，不在本仓库。

## 性能

### 测法

`test/ans48_bench`：按真实节奏送数据（每次一个 hop：耳返 128 样本 = 2.67 ms，推流 512 样本 = 10.7 ms，48 kHz），用 `taskset` 把进程钉在指定核心上跑 30 s，统计处理线程的 CPU 时间 / 墙钟时间（= 该核心被占用的比例）、每块耗时与超时（单块超过一个块周期）次数；另以全速（不睡眠）跑 10 s 量实时率。按真实节奏时核心会降频，所以占用率比全速实时率高，前者才反映实际运行时的占用。

```sh
adb shell 'cd /data/local/tmp/ans48 && LD_LIBRARY_PATH=. taskset <核心掩码> ./ans48_bench 00d2fda6_in48k.pcm 48000 <monitor|stream> 30 1'
```

- **推流档**任何核心都跑得下：大 / 中核约 6–12%，小核约 19–46%。**频谱档**比推流档多约 20%（每帧略快，但每秒帧数多 1/3）；与 aec48 串接时最紧的是 32 位小核，整块平均约 5 ms、最大约 7.3 ms（块周期 8 ms），建议 aec48 的处理线程放在大 / 中核。
- **耳返档仍建议放在大 / 中核上**：大 / 中核占用 30–49%，基本不超时；小核占用 65–80%，按真实节奏仍有约 1%（32 位最多 5%）的块超过一个块周期。实际接入时建议：处理线程固定在大 / 中核（Android 的 `APerformanceHint` / 提高线程优先级），或在两次处理之间让线程保持忙碌，让调频器维持高频；块与块之间留至少一块的缓冲。
- 按真实节奏时核心被调频压到低频，占用明显高于全速实时率；小核上偶发的长块（最大 10–25 ms）来自调度与调频，不是每块的计算量。
- 64 位明显快于 32 位（全速实时率约省 15–55%），优先用 arm64-v8a。
- 内存：每个实例常驻约 2.0–3.4 MB（含一份权重拷贝）；库文件 arm64 3.6 MB、armv7 3.5 MB（三档权重编在库内）。
- Galaxy S10 息屏进入打盹状态时，系统不允许把进程钉到中 / 大核（`taskset` 报 Invalid argument），测中核时须点亮屏幕。

## 版本与模型

- 当前：`ans48 0.3.0 (monitor ulunas-w256 e50, stream ulunas-w1024 e73, spec ulunas-w1536 e37)`。
- 0.3.0 修改：
  - **【联动】新增频谱档**，挂在 aec48 的频谱回调上，直接在回声消除后的频谱上降噪，不另加延迟。接口为 `ans48_create_spec`、`ans48_spec_frame`、`ANS48_SPEC_CONTRACT_VERSION`（= 1），见「⚠ 联动接口」一节。
    - 模型与推流档结构相同，按 aec48 的分帧（窗 1536、帧移 384、周期 sqrt-Hann）从推流档权重起步微调；两个采样率共用一份网络权重。
    - 与推流档在同一批 400 条验证集上比：降噪提升 48 kHz +1.28 → +1.67 dB、44.1 kHz +1.52 → +1.90 dB；干净人声保真持平或略高（46.2 → 46.4 / 46.6 dB）。
    - 每秒耗时比推流档多约 20%：每帧略快，但每秒帧数多 1/3。
  - **推流档强度上限 1 → 2**，与另两档相同。
  - **提速（模型与输出不变，对参照仍为 −100 ~ −104 dB、最大差 1 LSB）**：Galaxy S10 全速每帧耗时，中核约降 20%，小核约降 16%：
    - 深度卷积改为抽头数编译期固定、16 点 4 个累加器；
    - 步长 2 的普通卷积共用一次补零并拆成奇偶两段连续读，转置卷积改为聚集；
    - 逐点卷积权重预先转置，按 4 输出 × 8 频点计算；
    - 频率注意力的正反两个方向交错计算并向量化；
    - 双路 GRNN 的 4 条频率方向递推交错计算。
  - 权重打包：推流档、频谱档两个采样率共用网络权重，只各存 ERB 投影。库文件 arm64 3.6 MB（多了频谱档）。
  - 新增 `test/ans48_speccheck`（频谱档对参照）、`test/ans48_aecchain`（与 aec48 串联核对，编译时给 aec48 目录才编）。
- 0.2.1 修改：0.2 新接入的 pffft 在建 FFT 时没有检查内存分配失败，内存不足时 `ans48_create` 会使宿主进程崩溃（应返回 NULL）。已补上检查（对 pffft 的修改见 THIRD_PARTY_NOTICES）。新增 `test/ans48_oom`（Linux 主机）：让建实例过程中的每一次内存分配逐次失败，确认都返回 NULL、不崩溃。处理结果与 0.2 相同。
- 0.2 修改（模型不变；对参照实现的自检仍为 −100 ~ −104 dB、最大差 1 LSB）：落端提速，核心占用约降一半到三分之二，见性能表。
  - tanh / sigmoid 改用有理函数逼近（最大误差 3.3e-7，可向量化、无溢出），原先每帧几千次 libm 调用是最大的单项开销；
  - 逐点卷积改为 4 输出通道 × 4 频点的寄存器分块；深度卷积与步长 2 的普通 / 转置卷积改为先补零、按抽头整行乘加（去掉边界判断与分支）；
  - 小尺寸 GRU 单步与 16×16 全连接按固定尺寸展开，大 GRU 与全连接一次处理 4 行；
  - ERB 投影只算三角滤波器的非零段（矩阵只有 3% 非零）；
  - 外圈 FFT 改用 pffft 的实数 FFT（NEON）；
  - 双路 GRNN 全程在 (通道, 频点) 布局里算：输入投影、门值与全连接按逐点卷积整块算，时间方向 GRU 的 F 个频点一起算，去掉前后两次整块转置；频率方向 GRU 的递推按固定尺寸展开；
  - 卷积后的仿射 + PReLU 并进卷积输出（每写完一行就地做）；通道洗牌并进下一层深度卷积的读取，或并进 cTFA 的最后一遍（连同残差），不再单独拷贝。
- 0.1.1 修改：输出缓冲的读写计数器改为 64 位、可读判断改为"读写位置不相等"。0.1 在 32 位（armeabi-v7a）上计数器约 24.9 小时（48 kHz）回绕，之后持续输出 0 而接口照常返回成功。新增 `test/ans48_wrap`：把计数器设到 2^32 / 2^64 回绕点前处理，输出与从 0 开始逐样本相同。
- 网络为 UL-UNAS 结构的降噪掩码模型（约 15.4 万 / 20.3 万参数，耳返 / 推流；频谱档的网络结构与推流档相同），以 44.1 kHz 训练；48 kHz 下按 48 kHz 的频率刻度重建 ERB 投影。耳返档两个采样率的权重相同（高频段 64 个频点对 64 个 ERB 频带，投影与采样率无关）。
- 推理为手写流式实现（逐帧、显式状态、BatchNorm 折进卷积、每帧零分配），不依赖推理框架；FFT 用 pffft（NEON）。

## 已知限制

- 只处理单声道；只支持 48 kHz 与 44.1 kHz。
- 模型以 44.1 kHz 训练，48 kHz 下按频率刻度重建 ERB 投影后使用；两个采样率的效果是否完全等价未单独评估。
- 降的是稳态与准稳态噪声；与人声同时出现、频谱相近的非稳态干扰（例如旁人说话、伴奏）不在设计目标内。
- 只提供 C 接口；Java / Kotlin 直接调用需要自行写 JNI 包装。
